# Debug Assistant Guide

Generated by `scripts/dev/generate_debug_docs.py`.

## Overview

GrandpaAssistant includes a local, backend-only debug assistant system for turning visible errors and troubleshooting context into safe reports, fix plans, approvals, audit trails, debug sessions, exports, timelines, search results, reuse suggestions, learning summaries, preflight checks, and a combined debug health dashboard.

The system is designed for Windows-first local use. It does not need the removed frontend or mobile workspaces, and it keeps sensitive troubleshooting data local.

## Local Data Files

Debug runtime data is local and ignored by git:

- `backend/data/audit/fix_audit.jsonl`
- `backend/data/debug/debug_sessions.jsonl`
- `backend/data/debug/exports/`
- `runtime/data/last_backend_validation.json`

The docs generator exports no secrets and does not export runtime data, audit logs, screenshots, OCR text, tokens, or credentials.

## Safety Model

- Debug reports and fix plans are suggestion-first.
- Suggested commands are not executed automatically.
- Fix approvals require an explicit unique approval id.
- Risky commands are blocked or marked manual-only.
- Optional hardware and services, such as Ollama, microphone, camera, and OCR, report warnings instead of failing the whole debug system.
- API access for debug data is restricted to localhost or authenticated admin sessions.

## What Never Runs Automatically

- Terminal commands
- File edits
- Package installation
- Process termination
- File deletion, move, or rename
- Git reset or force push
- Clicks, typing, or application control
- Sending screenshots or screen text outside the local machine

## Approval Flow

The fix approval flow creates a pending approval item with a unique id. The assistant shows the exact proposed action, why it was suggested, and whether it is runnable.

Only safe read-only commands can run after `allow <id>`. Examples include `git status`, `python -m pip show <package>`, `python -m py_compile <file>`, `dir <path>`, `netstat -ano | findstr :<port>`, `Get-Process -Id <pid>`, and `whoami`.

Placeholders such as `<path>` or `<pid>` block execution until the user supplies a concrete value. Risky commands such as `pip install`, `npm install`, `Stop-Process`, `taskkill`, `git reset`, `git push --force`, and file delete/move/rename operations are not run by the safe approval flow.

## Audit Log

Fix approval creation, dismissal, execution, blocked actions, failures, and timeouts are recorded in `backend/data/audit/fix_audit.jsonl`. Audit entries redact private-looking values and truncate long command output.

Use `show fix audit log`, `fix audit`, or `last fix actions` for a quick assistant summary. Use `GET /api/debug/fix-audit` for local/admin API access.

## Debug Sessions

Debug sessions group reports, fix plans, approvals, and audit events into one local troubleshooting flow. Use `start debug session`, `current debug session`, `debug session summary`, `close debug session`, or `list debug sessions`.

Session APIs are available at `GET /api/debug/session/current`, `GET /api/debug/sessions`, `POST /api/debug/session/start`, and `POST /api/debug/session/close`.

## Export Reports

Use `export debug session`, `save debug report`, `export latest debug`, or `debug report file` to create a safe Markdown report under `backend/data/debug/exports/`.

Exports include session summaries, fix plan summaries, approval summaries, audit summaries, safety notes, and a timeline section when available. They do not include raw screenshots or binary data.

## Timeline

The debug timeline combines debug reports, fix plans, approvals, and audit events into chronological items with timestamps, event types, summaries, and safety flags.

Use `debug timeline`, `show debug timeline`, `what happened in debug session`, or `debug history`. API access is available at `GET /api/debug/timeline`.

## Search, Reuse, And Learning Summary

Debug session search finds old troubleshooting sessions by keyword, error family, fix plan summary, approval command, or audit event. Use `search debug sessions for <query>`, `find debug session <query>`, `old debug issue <query>`, or `previous error <query>`.

Reuse suggestions compare the current issue to prior debug history. Use `seen this before`, `similar debug history`, `previous fix for this`, or `idhu munnadi vandhucha`.

The learning summary counts repeated error families and safe fix patterns, then suggests preventive improvements. Use `debug learning summary`, `what did we learn from debug history`, `common debug errors`, `repeated issues`, or `debug insights`.

## Preflight Checklist

The preventive debug checklist generates and runs safe read-only checks for dependency/venv readiness, git status, port readiness, permissions, file paths, validation script availability, and optional Ollama readiness.

Use `run debug checklist`, `preflight debug check`, `preventive debug check`, `debug checklist`, or `issue varama check pannu`. The API route is `GET /api/debug/preflight-checklist`.

The checklist never installs packages, stops processes, edits files, deletes files, resets git, or runs destructive commands.

## Debug Dashboard

The debug health dashboard combines the active debug session, timeline count, learning summary, preflight status, pending approvals, recent audit events, export count, and reuse suggestions into one status payload.

Use `debug dashboard`, `debug health`, `debug status`, or `troubleshooting dashboard`. The API route is `GET /api/debug/dashboard`.

Optional warnings, including Ollama being unavailable, do not fail the dashboard by themselves. The payload includes `no_destructive_action = true`.
